# ইভেন্ট ড্যাশবোর্ড (Event Dashboard)

ইভেন্ট ড্যাশবোর্ড (`acd.toolforge.org`) উইকিমিডিয়া আউটরিচ ইভেন্ট, কর্মশালা ও এডিটাথনের জন্য একটি ওয়েব টুল। অংশগ্রহণকারীরা মোবাইল থেকে QR কোড স্ক্যান করে উইকিপিডিয়া অ্যাকাউন্টের আবেদন করেন, আয়োজকরা (স্থানীয় প্রশাসক) এক ক্লিকে বা একসাথে অনেক অ্যাকাউন্ট তৈরি করেন, আর ইভেন্ট চলাকালীন সবার অগ্রগতি লাইভ লিডারবোর্ডে দেখা যায়।

## বৈশিষ্ট্যসমূহ (Features)

**অংশগ্রহণকারীদের জন্য**
- মোবাইল-বান্ধব আবেদন ফর্ম: ইমেইল দুবার লেখা, সাধারণ বানান ভুলের পরামর্শ (যেমন `gmial.com` → `gmail.com`), উইকিপিডিয়ায় নামটি কেমন দেখাবে তার প্রিভিউ।
- লাইভ ব্যবহারকারী নাম পরীক্ষা: নামটি আছে কিনা (লোকাল ও SUL), AntiSpoof সংঘাত এবং নিষিদ্ধ নামের তালিকা (title blacklist)। নাম না পেলে খালি থাকা বিকল্প নাম দেখায়।
- আবেদনের অবস্থার পাতা (`/status/...`): অপেক্ষমাণ → তৈরি হয়েছে (পরবর্তী করণীয়সহ) → বাতিল (কারণসহ)। পাতাটি নিজে থেকে হালনাগাদ হয়।
- আগে থেকে অ্যাকাউন্ট থাকলে "আমার অ্যাকাউন্ট আছে" ট্যাব থেকে নিজেই ইভেন্টে যুক্ত হওয়া।
- ইমেইল ব্যবহারে সম্মতি ও গোপনীয়তা পাতা; সিদ্ধান্তের ৯০ দিন পর ইমেইল স্বয়ংক্রিয়ভাবে মুছে ফেলা হয়।

**আয়োজকদের জন্য**
- উইকিমিডিয়া OAuth 2.0 লগ ইন; `bn.wikipedia.org` / `bd.wikimedia.org`-এ নির্দিষ্ট গ্রুপের সদস্যরাই প্রবেশ করতে পারেন।
- প্রতিটি ইভেন্টের আলাদা পাতা: আবেদন, অংশগ্রহণকারী ও সেটিংস ট্যাব।
- লাইভ আবেদনের তালিকা (প্রতি ১০ সেকেন্ডে হালনাগাদ), এক ক্লিকে অনুমোদন, একসাথে অনেক আবেদন অনুমোদন/বাতিল (অগ্রগতিসহ), নাম পরিবর্তন।
- উইকিপিডিয়ার ত্রুটিগুলোর সহজ বাংলা ব্যাখ্যা; আগে তৈরি হয়ে যাওয়া অ্যাকাউন্ট স্বয়ংক্রিয়ভাবে শনাক্ত।
- প্রতি ইভেন্টে আলাদা স্বাগত বার্তা, নির্দেশনা, অ্যাকাউন্ট তৈরির উইকি ও লক্ষ্যমাত্রা।
- অংশগ্রহণকারী যোগ (উইকিতে যাচাই করে), বাদ দেওয়া ও ফিরিয়ে আনা; CSV ডাউনলোড; কার্যক্রমের লগ (ডেভেলপারদের জন্য)।
- প্রজেক্টর পাতা (`/event/<id>/display`): বড় QR কোড, নিবন্ধনের সংখ্যা ও শীর্ষ ১০।

**পরিসংখ্যান**
- মোট সম্পাদনা, নতুন নিবন্ধ, সম্পাদিত পাতা, ফাইল আপলোড ও যুক্ত বাইট; সময়ভিত্তিক চার্ট; প্রত্যেকের সম্পাদনার তালিকা; লিডারবোর্ড সাজানো ও খোঁজা।
- উইকির API-তে একবারে ৫০ জনের তথ্য চাওয়া হয় এবং প্রতিবার শুধু নতুন সম্পাদনা আনা হয়, তাই বড় ইভেন্টেও দ্রুত।

## প্রযুক্তি (Tech stack)

- **ব্যাকএন্ড:** Node.js 18+ (Express 4), EJS টেমপ্লেট
- **ডাটাবেজ:** SQLite (`better-sqlite3`), সংস্করণভিত্তিক মাইগ্রেশন
- **ফ্রন্টএন্ড:** Tailwind CSS (আগে থেকে বিল্ড করা), নিজস্ব সার্ভারের ফন্ট ও আইকন; কোনো বাইরের CDN নেই, কঠোর Content-Security-Policy
- **টেস্ট:** `node:test`, উইকি ও OAuth-এর একটি স্টাব সার্ভার (`test/helpers/mock-wiki.js`), ESLint, GitHub Actions

```
server.js            চালু করার ফাইল
src/                 সার্ভারের কোড (config, db, wiki, oauth, stats, routes/…)
views/               EJS পাতা ও partials
public/              CSS, JS, ফন্ট, আইকন (সরাসরি পরিবেশিত)
scripts/             অ্যাসেট বিল্ড স্ক্রিপ্ট
test/                টেস্ট
```

## লোকাল সেটআপ (Local setup)

```bash
npm install
cp .env.example .env
```

`.env`-এ লোকাল পরীক্ষার জন্য অন্তত এটুকু দিন:

```env
ENABLE_MOCK_LOGIN=true
DEVELOPER_USERNAMES=Yahya
```

তারপর:

```bash
npm run dev        # কোড বদলালে নিজে থেকে রিস্টার্ট
```

ব্রাউজারে `http://localhost:3000` খুলুন। মক লগ ইন চালু থাকলে `http://localhost:3000/login?user=Yahya` (ডেভেলপার হিসেবে) বা `/login?user=Test&wiki=bd` দিয়ে OAuth ছাড়াই অ্যাডমিন হিসেবে ঢোকা যায়। মক মোডে অনুমোদন করলে উইকিপিডিয়ায় আসল অ্যাকাউন্ট তৈরি হয় না; নাম পরীক্ষা ও পরিসংখ্যান আসল উইকিপিডিয়া থেকেই আসে।

অন্যান্য কমান্ড:

```bash
npm test           # সব টেস্ট (ইন্টারনেট লাগে না)
npm run lint       # ESLint
npm run build      # CSS, ফন্ট ও আইকন আবার তৈরি (views বা public/js বদলালে চালান এবং ফলাফল commit করুন)
```

## কনফিগারেশন (.env)

| ভেরিয়েবল | কাজ |
|---|---|
| `NODE_ENV` | Toolforge-এ `production` দিন। সিকিউর কুকি, প্রক্সি বিশ্বাস ও কঠোর যাচাই চালু করে। |
| `TRUST_PROXY` | অ্যাপের সামনে কয়টি প্রক্সি (Toolforge: `1`)। production-এ ডিফল্ট `1`। |
| `PUBLIC_URL` | QR কোড ও লিংকে ব্যবহৃত ঠিকানা, যেমন `https://acd.toolforge.org`। |
| `WIKIMEDIA_CLIENT_ID`, `WIKIMEDIA_CLIENT_SECRET`, `WIKIMEDIA_REDIRECT_URI` | উইকিমিডিয়া OAuth 2.0 কনজিউমার (নিচে দেখুন)। |
| `SESSION_SECRET` | production-এ কমপক্ষে ১৬ অক্ষরের র‍্যান্ডম স্ট্রিং আবশ্যক। |
| `DEVELOPER_USERNAMES` | ডেভেলপার (সুপার অ্যাডমিন) ব্যবহারকারী নাম, কমা দিয়ে আলাদা। এরা ইমেইল দেখতে, লগ ডাউনলোড করতে ও ইভেন্ট মুছতে পারেন। |
| `ALLOWED_GROUPS` | কোন উইকি গ্রুপের সদস্যরা অ্যাডমিন প্যানেলে ঢুকতে পারবেন (ডিফল্ট `sysop`; যেমন `sysop,accountcreator`)। |
| `ADMIN_WIKIS` | যে উইকিগুলোতে গ্রুপ যাচাই হয় (ডিফল্ট `bn.wikipedia.org,bd.wikimedia.org`)। |
| `EMAIL_RETENTION_DAYS` | সিদ্ধান্তের কত দিন পর ইমেইল মুছবে (ডিফল্ট `90`)। |
| `STATS_POLL_MINUTES` | পরিসংখ্যান কত মিনিট পর পর হালনাগাদ হবে (ডিফল্ট `5`)। |
| `DB_PATH` | ডাটাবেজ ফাইলের পথ (ডিফল্ট প্রজেক্ট ফোল্ডারের `database.sqlite`)। |
| `ENABLE_MOCK_LOGIN` | শুধু লোকাল পরীক্ষার জন্য। production-এ কাজ করে না। |

## Toolforge-এ হালনাগাদ করা (Upgrading on Toolforge)

নতুন সংস্করণ প্রথমবার চালু হলে ডাটাবেজ নিজে থেকেই নতুন কাঠামোয় রূপান্তরিত হয় এবং তার আগে একই ফোল্ডারে `database.backup-<সময়>.sqlite` নামে একটি ব্যাকআপ রাখে। পুরনো সব আবেদন, ইভেন্ট ও অংশগ্রহণকারী থেকে যায়; পরিসংখ্যান নতুন করে গণনা হয়।

```bash
ssh <shell-username>@login.toolforge.org
become acd
cd ~/www/js                      # টুলের কোড যেখানে আছে
cp database.sqlite ~/database.manual-backup.sqlite   # নিরাপত্তার জন্য আরেকটি কপি
git pull
webservice shell                 # webservice-এর মতো একই পরিবেশে ঢোকে
node --version                   # Node সংস্করণ দেখুন (১৮ বা তার বেশি হতে হবে)
npm ci --omit=dev                # better-sqlite3 সহ নির্ভরতা ইনস্টল
exit
webservice restart
```

`.env`-এ অবশ্যই থাকতে হবে:

```env
NODE_ENV=production
TRUST_PROXY=1
PUBLIC_URL=https://acd.toolforge.org
SESSION_SECRET=<কমপক্ষে ১৬ অক্ষরের র‍্যান্ডম স্ট্রিং>
DEVELOPER_USERNAMES=Yahya
WIKIMEDIA_CLIENT_ID=...
WIKIMEDIA_CLIENT_SECRET=...
WIKIMEDIA_REDIRECT_URI=https://acd.toolforge.org/auth/callback
```

`npm ci` যদি `better-sqlite3` বিল্ড করতে না পারে (Node সংস্করণের জন্য তৈরি বাইনারি না থাকলে), তাহলে `webservice` এর টাইপ বদলে নতুন Node সংস্করণ ব্যবহার করুন, অথবা সমস্যাটি জানান।

### SQLite ও একসাথে অনেক আবেদন

একটি কর্মশালায় একসাথে শতাধিক জন আবেদন করলেও SQLite-এ সমস্যা হয় না: সার্ভার একটি প্রসেসে চলে, প্রতিটি লেখা এক মিলিসেকেন্ডেরও কম সময় নেয় এবং লেখাগুলো ক্রমানুসারে হয়। সময় বেশি লাগে উইকিপিডিয়ার API-তে নাম পরীক্ষায়, ডাটাবেজে নয়। মনে রাখবেন:
- একই ডাটাবেজ ফাইলে অ্যাপের একাধিক কপি চালাবেন না (Toolforge-এর webservice ডিফল্টভাবে একটিই চালায়)।
- Toolforge-এর ফাইল NFS-এ থাকে, তাই অ্যাপ ইচ্ছাকৃতভাবে SQLite-এর WAL মোড ব্যবহার করে না।

## উইকিমিডিয়া OAuth 2.0 কনজিউমার প্রস্তাব

1. উইকিপিডিয়ায় লগ ইন অবস্থায় [Special:OAuthConsumerRegistration](https://meta.wikimedia.org/wiki/Special:OAuthConsumerRegistration/propose/oauth2) পাতায় যান।
2. নতুন কনজিউমারে দিন:
   - **Application Name:** `Wikimedia Bangladesh Outreach Toolkit`
   - **OAuth Version:** `OAuth 2.0`
   - **Callback URL:** `https://acd.toolforge.org/auth/callback`
   - **Grants:** *Basic rights*, *Create accounts*, এবং স্বাগত বার্তার জন্য *Edit existing pages* ও *Create, edit, and move pages*
3. অনুমোদনের পর পাওয়া **Client ID** ও **Client Secret** `.env`-এ বসান।
